# Captured output

Generated by `tools/capture_cli.py`, which runs the real command against a real PostgreSQL and records what came back. Regenerated by `make bench`; the timing lines are the only part that moves between runs.

## A handler with no memory, half the acknowledgements lost

```console
$ retry-amplification --handler naive --ack-loss 0.5 --messages 4000
naive handler, immediate retries, 4000 messages, 50% of acks lost, up to 5 attempts

reading                             measured   predicted
--------------------------------------------------------
attempts per message                   1.925       1.938
applications per message               1.925       1.938
never acknowledged                    0.0315      0.0312
--------------------------------------------------------
balance expected                        4000
balance found                           7699
units that should not exist             3699
median attempt                        0.494 ms
p99 attempt                           1.811 ms

3699 units of money exist that should not. No attempt raised an error, no delivery was dropped, and every component reported success.
Attempts were amplified 1.925x and every one of them applied, because the handler keeps no record of what it has already done.
$ echo $?
4
```

## A scenario that cannot produce a trustworthy number

```console
$ retry-amplification --ack-loss 1.0
invalid scenario: ack_loss=1.0 must be in [0, 1). At 1 every acknowledgement is lost, so no message ever completes and the run measures the retry cap rather than the delivery.
$ echo $?
2
```
